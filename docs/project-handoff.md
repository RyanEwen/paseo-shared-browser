# Shared Browser project handoff

Shared Browser is maintained in this standalone repository. The previous local `paseo-plugins` project and its feature worktrees were retired at the owner's request on 2026-10-16. The upstream monorepo and the original GitHub fork were not deleted. See [standalone migration](standalone-migration.md) for the original commit mapping and instructions for future upstream contributions.

## Feature decisions

Keep all existing fork features active, including Android video, direct native keyboard input, the agent device tool, WSL graphics, explicit agent recovery, and independent browser tabs. Adopt compatible upstream fixes and defaults; upstream deferral of a feature is not permission to remove it here.

Trusted agent attachment selects a 60-second screenshot receipt and five-minute idle control and viewer leases. Public viewer attachment keeps its existing 5-second frame, 30-second control, and 45-second heartbeat policy. Never infer agent trust from a label. Receipt authority is separated between human and agent observations of the same cached frame. Human takeover remains immediate, and navigation, viewport, document, runtime, attachment, and control fences still apply. Native gesture cleanup has a separate five-second idle timer; it does not reduce the agent screenshot lifetime. Effective policy is exposed in agent state and descriptions.

## Independent native windows and tab closing

New workspace attachment reserves a runtime generation but does not launch Chromium, its display or its profile. The focused lazy owner starts the existing process owner only for an explicit first URL or New Tab. It always launches at `about:blank` and then navigates that launch page to a requested URL as an ordinary page operation, so an unreachable or slow first destination leaves a usable page rather than a lost workspace. The error (`FirstPageNavigationError`, `UNKNOWN_OUTCOME` for a timeout) carries the viewer's new state, and agents follow that page. Never-started reservations with no viewers are not evicted yet; the 32 reservation cap makes that a distant limit. The detached supervisor creates its process owner once at start from its own directory (`dirname(argv[1])`), including Wayland and media assets, so it keeps launching its own runtime's binaries after a later install moves the pointer. Reservations are cheap: the supervisor tracks up to 32, while the lazy owner limits running browsers to 8 by claiming a slot synchronously before any native work, and empty reservations are not listed as open browsers. Unconfirmed cleanup after a failed launch keeps a retry handle; `stop()` retries it and refuses replacement only while the retry fails. `status:"empty"` has no selected content target, pixels, native document or emulation. Empty viewers retain normal viewer/control leases; first URL publication moves only the initiating viewer to the exact new page after lease, selection and runtime revalidation. Other empty viewers can discover and explicitly select it. Existing content selections and profile data remain independent. A pre-launch refusal leaves the unused reservation reusable. A clean startup failure is lost until explicit reattachment; unconfirmed process cleanup refuses replacement. A post-launch refusal is an unknown outcome with a discoverable page and no replay. Final-tab shutdown keeps its existing authority fences; bare explicit reopening creates a fresh empty generation.

The empty-workspace contract uses internal wire protocol 3, with package versions unchanged. Its IPC and startup lock intentionally retain the `supervisor-v2` directory: bridges must match the supervisor's wire revision, and a new executable cannot evade the old supervisor's lock by creating a parallel namespace. Agent adapters are the exception. Paseo saves each agent's MCP command, including its absolute script path, at creation, so agents created before an upgrade keep launching their original adapter. The 2026-10-27 wire 3 deployment stranded those agents with "Supervisor endpoint protocol mismatch". The supervisor therefore also admits wire 2 `agent.request` messages: those adapters pass replies through unchanged, so they get the empty-workspace behaviour too. Its endpoint file keeps `version: 2` for them and lists `protocols: [2, 3]` for current clients, which refuse an endpoint without their revision. Bridge and admin requests still require wire 3.

New agents save a fixed launcher path, `plugin-data/shared-browser/shared-browser-mcp.cjs`, instead of a runtime directory. The plugin rewrites it on start. When a session starts, the launcher loads the adapter that the running supervisor published in its endpoint file (`adapter`), but only while the published `pid` is alive. It takes just the `.runtime-*` directory name from that path and resolves it under its own plugin-data root, so the file cannot redirect it elsewhere and symlinked homes still match. With no supervisor running, it follows `runtime-current`, whose supervisor the plugin then starts. An install that moves the pointer before its approved supervisor replacement therefore cannot hand agents a newer adapter. Only agents created before this launcher remain pinned. Wire 2 replies about an empty workspace carry a `hint` naming those adapters' own tools, because their descriptions predate empty workspaces. Never delete old `.runtime-*` directories while agents that pinned them exist. If the launcher cannot be written, agent creation falls back to the runtime path and logs the failure. Activate matched plugin and runtime bundles only after the existing affected-session state-loss approval. A plugin-only reload cannot upgrade a detached supervisor. The [empty startup investigation](lazy-start-investigation.md) records process-free observation, first URL/New Tab flows, failure fences, retained site data and the unchanged-baseline mounted video limitation.

Ryan approved one invisible native window per content tab to satisfy browser-side WebAuthn visibility without changing independent viewer selections. The hidden window manager uses exact debugger/native-tab identity, preserves existing browsing contexts and opener relationships, and excludes capture helpers and print previews. No new extension permissions are required. Headless and owned private displays are supported; real-desktop headed launches are rejected before starting Chromium. Keep image-only raster policy separate from idle extension availability.

Safe identity/state/tab observations can recreate the hidden manager and its browser-management connection only while the original nonce-owned browser is alive. This remains possible after the launch content tab closes. Never adopt a survivor as the root page, replace the process, or replay an uncertain action during recovery. Input fails closed until native target readiness is known.

Ordinary tab closure requires an active viewer and exact runtime/tab/selection fences, with explicit human confirmation, but does not require control. Final-tab closure still requires control and explicit `last-tab` scope, and preview survivors still refuse browser shutdown. Cleanup before close publication must be reversible if authority expires; permanent controller retirement follows confirmed target disappearance.

The [focus investigation](page-focus-investigation.md) records Linux Chrome 155 headless/Xvfb/Wayland admission, popup identity, independent capture, management-loss recovery and real print/close evidence. It also records the immediate-script popup race, untested real passkey enrollment and native cross-platform limits, zero measured colour change from HEAD without a fidelity claim, and an unchanged-HEAD forced-screencast recovery failure. That failure was diagnosed and fixed on 2026-11-10: the JPEG screencast was started without size bounds, so under device emulation on the forced 2x native display Chromium emitted frames at the compositor surface size (824x1678 for a Pixel 7 at capture scale 1), and every frame was rejected as a dimension mismatch before it could count as recovery evidence. `Page.startScreencast` now passes the capture contract as `maxWidth`/`maxHeight`, which Chromium scales down to and never up; the retained smoke test readmits `cdp-screencast` about 1.2 seconds after the stream restarts, once the 1.5 second fallback dwell elapses. The policy thresholds and the capture-induced event exclusion are unchanged.

## Frame freshness and error recovery

Semantic element actions must not pass a V8 execution deadline. Chromium's deadline includes the application microtask checkpoint and can discard React's queued work after the action already computed a successful acknowledgement. Use the native-input CDP response wait instead; an expired response is an unknown outcome, never permission to terminate the page or replay the action. Bounded snapshot/inspection execution and all control/document/element fences remain separate. Element actions need no frame receipt; screenshot-coordinate input still uses its own freshness policy. The [DOM scheduling investigation](dom-scheduling-investigation.md) records the exact failure, correction and qualification limits.

Healthy empty video reads cannot renew painted-frame input authority. The existing 2.5-second watchdog requests fresh image/video pixels before the human five-second receipt expires, keeping old video visible only until the exact replacement decodes. Do not extend frame TTLs, relabel source timestamps or replay clicks to hide freshness failures. The [frame investigation](stale-frame-investigation.md) records the exact age5126 reproduction, layered native/policy/mounted proofs and unresolved live capture trigger.

Notices are dismissible per occurrence and panel scope. Relevant successful actions clear only the failure they observed at publication; old success must never hide a newer failure. Dismissal changes presentation only. Native passkey chooser capture/input remains a separate pending decision; focus admission alone does not qualify complete passkey interaction.

## Mobile tab placement

View size (Fit to panel or Actual size) is a client-session choice for each exact host/workspace pair. The installation's query cache retains it across panel remounts without fetching or saving host settings. Other connected clients keep independent choices. Unloading the plugin or restarting the app clears this session-only preference. Keep view size separate from browser viewport/device dimensions and the explicitly controlled Fill viewport action.

The mounted `--fixture view-size` check in `scripts/test-panel-video-mounted.mjs` covers workspace leave/return and prop-only switches, both Actual and Fit, host/client isolation, and retention with immediate collection of ordinary inactive queries. It runs the production panel/menu/cache without browser mutations. Use the same `--tooling-root` convention as the layout fixture below.

The tab row follows the panel's existing touch-first policy: `layout.platform !== "web" || layout.compact`. All iOS and Android hosts, including wide tablets, place the page title and display status bar above the canvas, followed by tabs and then the address toolbar below the canvas. Compact web layouts do the same; other web layouts keep tabs above the address toolbar and the title/display status below the canvas. The host supplies `layout.compact`; this plugin does not introduce a width breakpoint or infer mobile from the remote browser's emulation settings.

Touch-first tabs fill the available list width and shrink as tabs are added, stopping at their existing compact/regular minimum widths (132/176 for other tabs, 200/230 for the selected tab and its actions). The list scrolls only when those minimums no longer fit; the new-tab button stays outside the scroll area. Desktop tabs retain their fixed widths.

Bottom tabs and toolbar stay in the panel's normal flex flow, with a top separator on the tabs. Toolbar menus use the existing measured placement to open upward when there is more room above the trigger. Their height does not shrink, and the mobile canvas can shrink below its usual minimum when the host assigns a shorter panel, including keyboard-driven resizing. The tab row does not pin to the physical screen or add its own safe-area inset: host panel bounds remain responsible for system safe areas and keyboard avoidance. The SDK supplies no panel inset value. Existing native typing and Compose controls retain their lifecycle and ownership checks. Actual keyboard overlay/resizing and device safe-area behavior still require host/device verification.

The isolated mounted harness checks title/display, canvas, tab and toolbar order, separator/minimum-height styles, selected-tab accessibility, and available actions with production panel logic and DOM leaf doubles. Run `node scripts/test-panel-video-mounted.mjs --tooling-root <existing-host-tooling-root> --fixture tab-layout`, adding `--compact` and/or `--platform ios|android` for touch-first cases. It does not connect to a daemon or browser session, and JSDOM cannot qualify physical layout or native safe areas.

## Runtime and deployment lessons

Plugin reload replaces the bridge, then reconnects to an existing detached supervisor. It does not activate supervisor or capture implementation changes. A runtime replacement can close browser sessions and lose unsaved page state; obtain explicit approval for that concrete disruption after inventorying all supervisor-owned sessions. Never restart Paseo or unrelated agents to activate this plugin.

The empty-start release was deployed on 2026-11-10 with owner approval, closing two live pos-upgrade tabs. Paseo cannot apply a plugin `path` change without a daemon restart (`paseo reload` lists it as restart-required), so the registered directory `local-plugins/shared-browser-0.12.0-preview36-20261104` now holds the new build. Its previous contents are in `...-20261104.retired-20261110`, and `config.before-shared-browser-deploy-20261110.json` is the untouched config backup. Rename the registered directory only at a planned daemon restart.

Re-inventory live pages immediately before any supervisor replacement, not only when planning it; agents can open pages in between. On 2026-11-10 the plan was made with no Chromium running, but by deployment time another workspace had two live tabs. Disabling the plugin disconnects the supervisor's bridge and starts its orphan grace period (120 seconds), so re-enable it promptly if you stop. `prepare-runtime` moves `runtime-current` immediately; while the old plugin and supervisor keep running, point it back, or new agents will save the new adapter path against the old supervisor.

A previous JPEG failure followed a resolution change: the current schema allowed 800,000 bytes while an older detached supervisor emitted larger frames under the same protocol version. Validate the exact plugin/runtime combination in an isolated home. A protocol compatibility preflight before disconnecting the working bridge remains a future safeguard, not a completed migration feature.

The retirement source cutover changed only the registered plugin directory. It verified the same daemon, supervisor, immutable runtime, browser processes, and tab identities and URLs before and after bridge reload. Future development must use the isolated helper documented in AGENTS.md; this one approved cutover does not authorize further production lifecycle operations.

## Validation baseline

The 2.2.0 release adds empty workspace startup, Paseo++ 0.15 support, legacy adapter compatibility and the stable adapter launcher, and splits the four largest modules (panel, session policy, browser runtime, supervisor) into focused files behind unchanged facades. Its GitHub release was again a prerelease for the then-unresolved smoke gate. 2.2.1 fixes that recovery failure (unbounded screencast frames under emulation). Its video smoke failure was a stale test sending `tabs.close` without the session and runtime fences, and Windows smoke tests no longer request headed windows, which the independent-tab policy refuses.

The 2.1.0 standalone release adds explicit Paseo 0.12.0-preview.35 compatibility and local-directory preparation guidance. Every Vitest suite now excludes staged `.dev` copies and the private `.local-history` recovery archive. GitHub publication is a prerelease while the documented forced-screencast recovery smoke failure remains unresolved. The package name and `shared-browser` runtime ID retain upstream identity; this GitHub release does not publish the upstream-owned npm package.

The standalone baseline passed 784 unit tests, five script tests, build, typecheck, lint, and shrinkwrap checks. Linux, macOS, and Windows CI passed, including Linux native-video capture/decode. The exact GitHub-install path was also exercised on an isolated daemon and cleaned up.
